Recipe — Step 1

Apply the vigilance-as-process template

  1. Pick the scope where carelessness will apply.
  2. Stand up an empty guardian slot in your workflow.
  3. Stand up a one-step workflow: in → agent → out.
  4. Write down today's vigilance list — everything you currently watch for.
  5. Build a partial spot-checker. Cover only what's easy to catch.

Worked example — release notes

Setting up the loop

  • Scope: release notes for the current sprint.
  • Guardian slot: empty notes-linter stage in the pipeline.
  • Workflow: changelog + ticket list → agent → draft.
  • Vigilance list: tone drift, missed feature, leaked customer IDs, wrong version number.
  • Spot-checker: regex that flags any line containing a customer-ID pattern.

The loop is now standing. Time to start naming.

Recipe — Step 2

Name the vigilance

  1. Watch yourself reviewing the agent's output.
  2. Each correction: write the why in five words or fewer.
  3. Group the why-notes into three to five error categories.
  4. Pick the largest category. Give it a name.

Worked example — release notes

From corrections to a category

  • Tone too internal — 4 corrections.
  • Missed feature — 3 corrections.
  • Wrong version number — 2 corrections.

Named category: Tone drift.

Recipe — Step 3

Identify a hole

  1. Run the current spot-checker on a fresh agent output.
  2. Compare its findings against your manual review.
  3. What you caught but it missed = a hole. Write it down.

Worked example — release notes

A hole in the tone check

  • Spot-checker flagged tone drift in 2 of 4 known cases.
  • Common factor in the misses: features written in past tense.
  • Hole: past-tense phrasing bypasses the current pattern.

Recipe — Step 4

Lock one error category

  1. Pick the hole you understand best.
  2. Choose a universe lever that structurally prevents that class.
  3. Implement the change. Re-run against every prior failure case.

Worked example — release notes

Locking tone drift with Tooling

  • Lever chosen: Tooling.
  • Replace the freeform draft tool with a structured template that constrains tone via the schema (verb tense fixed; allowed phrasings whitelisted).
  • Verification: 0 of 12 prior tone-drift cases reproduce.

Recipe — Step 5

Adjust vigilance

  1. Remove the locked category from your vigilance list.
  2. Re-evaluate the remaining categories — ordering, severity, frequency.
  3. Pick the next one to attack in the next loop.

Worked example — release notes

The list shrinks

  • Tone drift — locked.
  • Missed feature — now top of the list.
  • Wrong version number — small and easy; queue after.

Next loop: name the missed-feature pattern.

Recipe — Step 6

Make a decision

  1. Look at the universe you've built.
  2. Decide: accept this run, or re-run inside the safer universe.
  3. Note the risk profile of whichever you chose, in writing.

Worked example — release notes

Three loops later

  • Universe catches: tone drift, wrong version number.
  • Residual risk: missed-feature — still at Hope level.
  • Decision: accept this run. Residual is bounded and visible.

The recipe ended. Vigilance about tone and version is gone, permanently.
